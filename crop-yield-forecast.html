How it works

The Python pipeline behind this page. It writes the forecast file that this dashboard reads.

  • One model per distance. A separate model forecasts 1, 2, … 8 weeks ahead, so errors don't build up the way they do when a 1-week model is fed its own forecasts.
  • No peeking at the future. The test year comes after all training weeks. The seasonal weather normals used in the test only come from weeks before it, and model tuning uses time-ordered folds.
  • Honest ranges. The 80% range comes from real backtest errors at each distance. It was learned on the first half of the test year and checked on the second half, where it held of weeks. That is a little narrow, mostly because of pest and disease dips that no input can see coming, so the range is a guide, not a guarantee.
  • Related inputs judged together. Crop age, plant height and nodes all measure crop stage, so they are shuffled as one group. Otherwise credit is split between near-copies and the chart misleads.
  • Crop cycles respected. Forecasts are zero before the first harvest age and after the age at which 90% of past cycles of that crop had ended.

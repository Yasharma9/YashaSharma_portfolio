What drives the forecast

How much the error grows when a group of inputs is shuffled (grouped permutation importance), as a share of the total, for the best model.

How it works

The Python pipeline behind this page. It writes the forecast file that this dashboard reads.

  • Accuracy = 100% − MAPE (mean absolute percentage error) on the held-out year. Weeks with less than 0.05 kg/m² are left out of MAPE, because percentages explode near zero; MAE and WAPE in the tables include every week.
  • One model per crop, chosen fairly. Every model is scored on 39 weeks before the test year, in 3 rolling folds, each predicted by models trained only on earlier weeks. The model with the lowest average error over all 8 distances is chosen. The test year plays no part in the choice, so its accuracy is a fair estimate of live accuracy.
  • One model per distance. Separate models forecast 1, 2, … 8 weeks ahead, so errors don't build up the way they do when a 1-week model is fed its own forecasts.
  • Inputs a grower has. Fruit set in the last 8 weeks (fruit that sets now is picked weeks later), the crop's typical yield curve from past cycles, lined up by the week harvest began, and the planned removal week. These carry most of the accuracy at the start and end of a crop.
  • No peeking at the future. Weather normals and typical yield curves used in the test come only from weeks before it; tuning uses time-ordered folds.
  • Honest ranges. The 80% range is the 10th to 90th percentile of past errors at each distance, per crop. Learned on the first half of the test year and checked on the second half, it held of weeks for this crop, so treat it as a guide.
